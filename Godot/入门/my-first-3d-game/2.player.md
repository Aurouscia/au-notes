# 创建玩家场景

新建一个场景，根节点为`CharacterBody3D`，将其重命名为`Player`。这种节点专门用于玩家，其有碰撞检测功能，但移动不受物理引擎控制，仅受代码控制。

## 模型

为 Player 添加一个 Node3D 子节点，重命名为 Pivot，它将会是角色旋转围绕的点。

然后将文件系统的 player.glb 拖动到 Pivot 中，它会新建一个 Node3D 节点，重命名为 Character

> `.glb` 文件包含了基于 glTF2.0 开放标准的 3D 数据。这是个强大的 FBX 专有格式替代品。为了产生这种文件，我们在 Blender 中设计 3D 模型，导出为 glTF

稍稍向上移动 Pivot（由于它是模型的父节点，会带着模型向上走），直到模型底部贴近地面。

## 碰撞箱

为 Player 节点添加 CollisionShape3D 子节点，以提供碰撞形状。选择 SphereShape3D。

可以在节点树中先隐藏 Character。选中 Shape，拖拽红色的点可以缩放这个线框。把它的大小调整到 0.8 左右，然后上移，底部对齐地面。

## 代码

为 Player 节点附加脚本

为其创建两个公共 Export 属性，分别为`Speed`和`FallAcceleration`，分别控制水平移动速度和下落加速度（模拟重力）

再创建一个 `_targetVelocity` Vector3 私有字段

覆写`_PhysicsProcess`勾子函数（该函数和 Process 的区别在于，它以固定间隔执行，适用于关于物理的动力学和刚体代码），定义一个 Vector3 direction，然后使用`Input.IsActionPressed`判断 WASD 的按下情况，根据按下情况 += 或 -= direction 的 X 轴和 Z 轴，以控制 direction 的指向。

如果 direction 不为零，那么进行一些操作：

```cs
    if (direction != Vector3.Zero)
    {
        // 单位化，避免斜向运动时产生 1.414 的长度
        direction = direction.Normalized();
        // 设置 Pivot 的局部坐标系，使其 -Z 方向朝向 direction，同时 Y 轴尽量朝上。如果 direction 不是单位向量，就会错误地引入缩放。
        GetNode<Node3D>("Pivot").Basis = Basis.LookingAt(direction);
    }
```

注意设置的是 Pivot 节点的局部坐标系，而不是 Player 的。这可以让 Player 的坐标系始终对齐全局，更便于 WASD 操作的计算。而 Pivot 专心控制模型的旋转方向。

接下来将方向转换为速度：

```cs
    _targetVelocity.X = direction.X * Speed;
    _targetVelocity.Z = direction.Z * Speed;
```

CharacterBody3D 内置了“是否在地板上”函数 `IsOnFloor`，可通过它判断是否需要下落（速度 Y 分量减为负数）

```cs
    if (!IsOnFloor())
    {
        _targetVelocity.Y -= FallAcceleration * (float)delta;
    }
```

最后，设置节点内置的 Velocity 属性，调用 MoveAndSlide 不仅可以让它根据自己的 Velocity 属性移动，还可以在撞到地面时维持水平方向的速度。

```cs
    Velocity = _targetVelocity;
    MoveAndSlide();
```

## 人工测试

把 Player 实例化到主场景的根节点

在主场景根节点下新建一个 Marker3D 节点，命名为 CameraPivot，其下再新建一个 Camera3D 节点，选择“正交视角”，Size 为大约 19 米

点击 3D 视图窗口上方的“视图”按钮，选择 2 个视口。其中一个用于 3D 场景操作，另一个勾选相机预览，用来实时查看效果

把 Camera3D 向 Z 轴正方向移动大约 19 米，然后将 CameraPivot 沿 X 轴选择（拖动红色圆圈），使 Camera 角度合适

启动游戏，确认 WASD 操作正常
