为什么相机对象和相机数据是两个东西？

这是 Blender 架构中一个非常重要的设计概念，涉及到 **Object（对象）** 与 **Data（数据）** 的分离。

## 核心原因：Blender 的 "Object-Data" 分离架构

Blender 中，你在 3D 视图中看到的、可以选中移动的"东西"是 **Object（对象）**，而对象内部引用的实际内容（几何体、相机参数、灯光属性等）是 **Data（数据块）**。它们是**两个独立的 data-block**。

```
Object（相机对象）
├── 位置、旋转、缩放（transform）
├── 层级关系（parent/child）
└── 引用 → Camera Data（相机数据）
    ├── 焦距（focal length）
    ├── 传感器尺寸
    ├── 景深设置
    └── ...
```

## 为什么要这样分离？

### 1. **数据复用**
多个 Object 可以共享同一个 Data。例如：
- 多个网格对象可以共用同一个 mesh data（如截图中的例外情况所述）
- 多个灯光对象可以共用同一种灯光类型和参数
- 多个相机对象理论上也可以共享同一套相机参数

### 2. **逻辑分层**
| Object 层 | Data 层 |
|-----------|---------|
| 这个相机**在哪里**（世界空间中的位置/旋转） | 这个相机**是什么参数**（焦距、光圈等） |
| 这个相机**属于哪个层级** | 这个相机**如何成像** |

这样分离后，你可以：
- 复制一个相机对象到另一个位置（新 Object），但保持相同的焦距设置（共享 Data）
- 或者复制相机参数给另一个相机，但让它们位于不同位置

### 3. **动画分离**
正因为它们是独立的 data-block，所以动画也是分开存储的：
- 相机对象的动画 → 存储在 Object 的 Action 中（位置、旋转变化）
- 相机数据的动画 → 存储在 Camera Data 的 Action 中（焦距、景深变化）

Blender 的"密切相关"启发式规则就是为了**在逻辑上把这两层动画合并到一个 Action 里**，方便管理。否则你会得到两个独立的 Action，一个管位置，一个管焦距，非常混乱。

## 其他例子

这个模式贯穿 Blender 的所有类型：

| Object 类型 | Data 类型 | Object 动画 | Data 动画 |
|-------------|-----------|-------------|-----------|
| Mesh Object | Mesh Data | 位置、旋转 | 顶点位置、形态键 |
| Light Object | Light Data | 位置、旋转 | 能量、颜色 |
| Camera Object | Camera Data | 位置、旋转 | 焦距、光圈 |
| Curve Object | Curve Data | 位置、旋转 | 曲线控制点 |

## 总结

相机对象和相机数据分开，不是因为它们"应该"分开，而是因为 Blender 的架构**把所有东西都设计为可复用的 data-block**。Object 是"容器/实例"，Data 是"实际内容"。这种分离带来了灵活性，而 Blender 的 Action 复用机制则是在这种灵活性之上做的**用户体验优化**——让密切相关的动画自动归到一起，减少管理负担。
