## 一、事件循环（Event Loop）

### 执行顺序（从高优先级到低）

```
1. 同步代码（Call Stack）
2. 微任务（Microtask）— 全部清空
   - Promise.then / catch / finally
   - queueMicrotask()
   - async/await 的后续代码（await 之后的部分）
   - MutationObserver
3. 宏任务（Macrotask）— 取一个执行
   - setTimeout / setInterval
   - I/O 操作
   - UI 渲染
4. 重复步骤 2-3
```

### 关键记忆点

- **微任务会在当前宏任务结束后立即全部执行**，而不是插入到下一个宏任务之前。
- `await` 会把后续代码变为微任务，但 `await` 右侧的表达式是同步执行的。
- 浏览器和 Node.js 的事件循环有差异：Node 有 phases（timers → I/O → poll → check → close），浏览器更简单。

### 示例对比

```js
// 示例1：await 右侧同步
async function f() {
  console.log('A');
  await console.log('B'); // B 是同步的
  console.log('C');       // C 是微任务
}
f();
console.log('D');
// 输出：A → B → D → C

// 示例2：Promise.then 的优先级
setTimeout(() => console.log('timeout'), 0);
Promise.resolve().then(() => console.log('promise'));
console.log('sync');
// 输出：sync → promise → timeout
```

## 二、this 绑定规则

### 四条规则（优先级由低到高）

| 规则 | 场景 | 示例 |
|------|------|------|
| **默认绑定** | 直接调用函数 | `foo()` → this = 全局（非严格）/ undefined（严格） |
| **隐式绑定** | 通过对象调用 | `obj.foo()` → this = obj |
| **显式绑定** | call / apply / bind | `foo.call(obj)` → this = obj |
| **new 绑定** | 构造函数 | `new Foo()` → this = 新实例 |

### 记忆口诀

> **默认 < 隐式 < 显式 < new**

### 例外：箭头函数

箭头函数没有自己的 `this`，继承外层作用域的 `this`（词法绑定）。

```js
const obj = {
  a: 1,
  fn: () => console.log(this.a), // this 指向定义时的外层
  fn2() { console.log(this.a); } // this 指向调用者
};
obj.fn();  // undefined（外层可能是全局）
obj.fn2(); // 1
```

## 三、Promise 核心

### Promise.all vs Promise.allSettled

| 特性 | Promise.all | Promise.allSettled |
|------|-------------|-------------------|
| 失败行为 | 快速失败（一个 reject 立即 reject） | 等待所有完成，无论成功失败 |
| 返回值 | 所有 resolve 的值数组 | `{status, value/reason}` 数组 |
| 适用场景 | 依赖全部成功，如事务操作 | 需要知道每个结果，如批量请求 |

### 其他常用组合

- `Promise.race` — 返回最快完成的那个（不论成功失败）
- `Promise.any` — 返回最快成功的那个，全部失败才 reject

## 四、类型转换与 ==

### 经典题：`[] == ![]` 为什么为 true？

1. `![]` → `false`（对象转布尔为 true，取反为 false）
2. `[] == false` → 比较时 [] 转为数字 0，false 也转为数字 0
3. `0 == 0` → `true`

### 记忆策略

- 优先使用 `===` 避免隐式转换
- 如果面试考 `==`，记住 **抽象相等比较算法** 的顺序：先转数字，再比较

## 五、闭包与作用域

### 经典题：var 在循环中的陷阱

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 100);
}
// 输出：3 3 3（var 是函数作用域，共享同一个 i）

// 修复方案：
// 1. 用 let（块级作用域）
// 2. 用 IIFE 创建私有作用域
for (var i = 0; i < 3; i++) {
  (function(j) {
    setTimeout(() => console.log(j), 100);
  })(i);
}
```

## 六、V8 性能优化（进阶）

### 隐藏类（Hidden Class / Shape）

- 相同结构的对象共享同一个隐藏类
- 动态增删属性会导致隐藏类变化，Inline Cache 失效
- **优化建议**：构造函数中初始化所有属性，避免运行时动态添加

```js
// 差：动态添加属性
const obj = { a: 1 };
obj.b = 2; // 隐藏类变化

// 好：预先声明
const obj = { a: 1, b: undefined };
obj.b = 2; // 隐藏类不变
```

### Inline Caching（内联缓存）

> V8 在属性访问上的热点优化机制。反复读取同一对象的属性时，缓存 "隐藏类 + 属性名 → 偏移量" 的映射，后续访问时先检查隐藏类是否匹配，匹配则直接按偏移量取值，跳过字典查找。

**工作流程：**
1. 首次访问：`obj.x` → 查隐藏类 → 记录偏移量 → 存入缓存
2. 后续访问：检查隐藏类是否匹配 → 命中则直接取偏移量 → 未命中回退慢路径

**为什么重要？**
- 属性查找从 **O(n) 字典查找** 变成 **O(1) 直接偏移**
- 动态增删属性导致隐藏类变化 → 缓存失效 → 性能回退

**总结口诀：** 同类对象共享隐藏类，属性访问走缓存，动态增删类就碎，预先声明最实惠。

## 七、new 运算符 — 设计意图与完整流程

### 完整步骤（不只是死记硬背）

```
1. 创建一个新的空对象
2. 将新对象的 [[Prototype]] 链接到构造函数的 prototype
3. 将构造函数中的 this 绑定到这个新对象
4. 执行构造函数代码（this.xxx = ...）
5. 如果构造函数显式返回了一个对象，返回该对象；否则返回新对象
```

### 设计意图解析 — 为什么要链接到构造函数的 prototype？

这不是一个随意的规定，而是 **面向对象继承体系的核心设计**。

**场景：构造函数是"工厂"，prototype 是"共享方法仓库"**

```js
function Person(name) {
  this.name = name;  // 实例独有的属性
}

// 方法放在 prototype 上，所有实例共享
Person.prototype.sayHi = function() {
  console.log('Hi, I am ' + this.name);
};

const p1 = new Person('Alice');
const p2 = new Person('Bob');

p1.sayHi(); // "Hi, I am Alice"
p2.sayHi(); // "Hi, I am Bob"
```

**为什么方法要放在 prototype 上而不是构造函数里？**

```js
// 差：每个实例都有一份独立的函数拷贝
function Person(name) {
  this.name = name;
  this.sayHi = function() {  // 每次 new 都创建新函数
    console.log('Hi, I am ' + this.name);
  };
}

const p1 = new Person('Alice');
const p2 = new Person('Bob');
console.log(p1.sayHi === p2.sayHi); // false — 浪费内存

// 好：方法放在 prototype 上，所有实例共享一份
function Person(name) {
  this.name = name;
}
Person.prototype.sayHi = function() { ... };

console.log(p1.sayHi === p2.sayHi); // true — 节省内存，便于统一管理
```

**所以链接 prototype 的目的：**
- 让实例 **共享** 构造函数 prototype 上的方法
- 实现 **原型链继承**：实例找不到的属性/方法，会沿着 `__proto__` → `prototype` → `Object.prototype` 向上查找
- 这是 JavaScript 实现 **类式继承** 的基础机制（虽然底层是原型链）

### "绑定 this" 具体指什么？

```js
function Person(name) {
  // 这里 this === 新创建的空对象 {}
  this.name = name;
  this.age = 20;
  // 执行后，this 变成了 { name: 'Alice', age: 20 }
}

const p = new Person('Alice');
```

**绑定 this 的本质：**
- 在构造函数内部，`this` 不是全局对象，不是 undefined，而是 **步骤1创建的那个新对象**
- 构造函数通过 `this.xxx = ...` 给这个新对象添加属性和方法
- 相当于：构造函数被 **call/apply** 了一样，`this` 被硬编码指向了新实例

**可以手动模拟 new：**

```js
function myNew(constructor, ...args) {
  // 1. 创建新对象
  const obj = {};
  // 2. 链接原型
  Object.setPrototypeOf(obj, constructor.prototype);
  // 3. 绑定 this 并执行构造函数
  const result = constructor.apply(obj, args);
  // 4. 处理返回值
  return result instanceof Object ? result : obj;
}

// 使用
const p = myNew(Person, 'Alice');
```

### 记忆策略

> 把 `new` 想象成一个 **"工厂装配流程"**：
> - 原材料（空对象）→ 装上身世档案（prototype）→ 赋予身份（绑定this）→ 填充属性（执行代码）→ 出厂（返回对象）

## 八、LRU 缓存 — O(1) 的魔法

### 问题背景

> "缓存满了要淘汰最久没用的，怎么做到 get/put 都是 O(1)？"

直觉上：淘汰最久没用的需要"排序"，排序至少是 O(log n) 或 O(n)。

答案是：**HashMap + 双向链表** —— 两个 O(1) 的数据结构组合。

### 两个数据结构的职责

| 数据结构 | 职责 | 时间复杂度 |
|---------|------|----------|
| **HashMap**（JavaScript 用 `Map`） | 存储 key → 链表节点的映射 | O(1) 查找 |
| **双向链表** | 维护"使用顺序" — 头部是最近使用的，尾部是最久没用的 | O(1) 插入/删除/移动 |

### 为什么双向链表是 O(1)？

因为每个节点保存了 `prev` 和 `next` 指针：
- **删除节点**：修改前后节点的指针即可，不需要遍历（`node.prev.next = node.next; node.next.prev = node.prev`）
- **移到头部**：先删除，再插入头部，都是指针操作
- **淘汰尾部**：直接取 `tail.prev`，删除它

### 完整实现

```js
class LRUCache {
  constructor(capacity) {
    this.capacity = capacity;
    this.map = new Map(); // key → node
    // 用哨兵节点简化边界判断
    this.head = { prev: null, next: null };
    this.tail = { prev: this.head, next: null };
    this.head.next = this.tail;
  }
  
  _remove(node) {
    node.prev.next = node.next;
    node.next.prev = node.prev;
  }
  
  _addToHead(node) {
    node.next = this.head.next;
    node.prev = this.head;
    this.head.next.prev = node;
    this.head.next = node;
  }
  
  get(key) {
    if (!this.map.has(key)) return -1;
    const node = this.map.get(key);
    // 访问了 = 最近使用，移到头部
    this._remove(node);
    this._addToHead(node);
    return node.value;
  }
  
  put(key, value) {
    if (this.map.has(key)) {
      // 更新已有值，先删除旧位置
      this._remove(this.map.get(key));
    }
    const node = { key, value };
    this._addToHead(node);   // 新数据/更新后的数据 = 最近使用
    this.map.set(key, node);
    
    if (this.map.size > this.capacity) {
      // 淘汰尾部（最久没用的）
      const lru = this.tail.prev;
      this._remove(lru);
      this.map.delete(lru.key);
    }
  }
}
```

### 时间复杂度分析

| 操作 | 步骤 | 复杂度 |
|------|------|--------|
| `get` | HashMap 查找 + 链表移动 | O(1) + O(1) = **O(1)** |
| `put` | HashMap 查找/设置 + 链表插入 + 可能淘汰尾部 | O(1) + O(1) + O(1) = **O(1)** |

### 为什么不能用普通对象 + 数组？

```js
// 错误方案：对象 + 数组记录顺序
{
  data: { a: 1, b: 2 },     // O(1) 查找
  order: ['a', 'b']         // 淘汰时需要找 index，splice 是 O(n)
}
```

数组的 `splice`（删除中间元素）和 `indexOf`（查找位置）都是 O(n)。链表没有这个问题，因为节点自己带着前后指针。

### 记忆策略

> **HashMap 管"找"，链表管"排"**。Map 让你瞬间找到数据，链表让你瞬间调整顺序。单用任何一个都做不到 O(1)，组合起来就是面试题的标准答案。
